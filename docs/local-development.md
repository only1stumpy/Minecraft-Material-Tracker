# Как запустить сайт на своём компьютере

Эта инструкция для человека, который впервые скачивает код Antville Builder. Сначала здесь собран список функций проекта, затем — шаги, после которых у вас откроется отдельная копия сайта по адресу `http://localhost:3000`.

Это закрытый проект. Локальная копия нужна для разработки и знакомства с кодом. Она не подключается к рабочему сайту и не содержит его данные. Здесь создаётся пустая база данных для версии 2.0; данные старой версии не переносятся.

## Что умеет Antville Builder 2.0

Ниже перечислены функции, которые уже есть в коде проекта. Это не обещание, что каждая из них проверена на рабочем сайте: внешние проверки собраны в [статусе реализации](v2-implementation-status.md).

### Для всех участников

- Вход по Minecraft-нику и паролю. Самостоятельной регистрации нет: аккаунты выдаёт администратор.
- Каталог построек с поиском по названию, описанию и автору; фильтрами по статусу; сортировкой по дате, названию и прогрессу; страницами каталога.
- Отдельные списки «Мои постройки», «Я участвую», «Избранное» и возможность скрыть завершённые постройки.
- Карточка постройки с описанием, координатами, автором и ответственным, скриншотом, статусом, списком ресурсов и прогрессом сбора и доставки.
- Создание карточек и редактирование тех, на которые у участника есть права.
- Список материалов можно загрузить из `.txt` или `.log`, вставить из Litematica или заполнить вручную. До сохранения строки можно проверить и поправить, добавить и удалить; одинаковые материалы можно объединить.
- Для материала можно указать нужное количество и размер стака. Участники берут объём в работу, отмечают собранное и доставленное, освобождают резерв. Сбор и доставка записываются отдельно от карточки; замена файла схемы не сбрасывает их.
- Для постройки можно добавить комментарий или написать его к конкретному материалу. Участники могут получить строительную задачу, отметить её начатой и завершённой.
- Изменения карточки и её материалы можно посмотреть в истории версий; доступную версию можно восстановить.
- Карточка обновляется, когда её меняет другой участник. При потере соединения сайт пробует подключиться снова.
- Внутренние уведомления: о назначении, смене статуса, резерве и сборе материалов, доставке, комментариях и смене роли. В профиле можно выбрать, какие уведомления получать.
- Профиль показывает вклад: созданные проекты и проекты с вашим вкладом, собранные и доставленные предметы, закрытые задачи и последние действия. Там же можно сменить Minecraft-ник, пароль и завершить все сеансы.

### Материалы города

- **Общий склад** показывает остатки и последние движения материалов. Можно записать приход, расход или установить точный остаток. Менять склад могут модераторы и администраторы.
- **Потребности города** складывают нужные ресурсы активных построек, учитывают сбор и доставку, затем вычитают остатки общего склада. Есть поиск и фильтр «Только дефицит».

### Для модераторов

- Редактирование карточек, в том числе чужих; смена статуса и владельца.
- Исправление ошибочно записанного чужого сбора.
- Скрытие и восстановление построек и комментариев.
- Поиск карточек и комментариев, просмотр похожих названий и последних ошибок импорта.
- Управление общим складом.

### Только для администраторов

- Создание аккаунтов игроков, модераторов и других администраторов.
- Блокировка и разблокировка аккаунтов, назначение роли, изменение Minecraft-ника и выдача нового временного пароля.
- Просмотр вклада участников, карточек и журнала важных действий.
- Доступ ко всем действиям модератора.

### Что пока не входит в обычную работу

- Самостоятельной регистрации, Telegram-уведомлений и подключения к игровому серверу Minecraft нет.
- Запуск по этой инструкции создаёт пустую локальную базу. Перенос данных старой SQLite-базы — отдельная операция; в текущий запуск 2.0 он не входит.
- Некоторые сценарии нужно отдельно проверять на рабочем окружении: например, вход нескольких реальных участников, загрузку файлов, резервное копирование и восстановление. Подробности есть в [статусе реализации](v2-implementation-status.md).

Интерфейс проекта оформлен в тёмных чёрно-бордовых цветах с полупрозрачными панелями; на телефоне основные страницы перестраиваются под узкий экран. Для крупных заголовков используется контрастная антиква Prata, для кнопок, форм и обычного текста — шрифт Onest с кириллицей. Next.js упаковывает файлы шрифтов вместе с сайтом, поэтому браузер посетителя не обращается к Google Fonts.

Если нужно изменить типографику или цвета, откройте `app/globals.css`: там находятся общие шрифтовые переменные, палитра и правила внешнего вида. Подключение файлов шрифта находится в `app/layout.tsx`.

## Что нужно попросить у владельца проекта

До установки попросите:

1. Приглашение в приватный репозиторий GitHub. Без него GitHub не даст скачать код.
2. Тестовый токен Vercel Blob, если на локальном сайте нужно загружать схемы и скриншоты. Если токена нет, сам сайт запускается, но загрузка файлов не работает.

Не просите и не используйте адрес рабочей базы данных. Не вставляйте пароли, токены и другие секреты в сообщения, GitHub или файлы проекта, кроме своего локального `.env`.

## Установите программы

Понадобятся четыре вещи:

- **Git** — скачивает код проекта. Установка: [git-scm.com](https://git-scm.com/downloads).
- **GitHub CLI (`gh`)** — помогает войти в GitHub из терминала. Установка: [cli.github.com](https://cli.github.com/).
- **Node.js** — запускает сайт и его инструменты. Проект поддерживает Node.js `22.12` и новее в ветке `22.x` или `24.11` и новее в ветке `24.x`. Установите одну из этих версий: [nodejs.org](https://nodejs.org/en/download/).
- **Docker Desktop** — запускает локальную базу данных PostgreSQL, не требуя ручной установки самой базы. Установка: [официальная инструкция Docker](https://docs.docker.com/desktop/).

Версии `23.x` и `25.x` сейчас проектом не поддерживаются.

Откройте терминал и проверьте, что программы доступны:

```sh
git --version
gh --version
node --version
npm --version
docker --version
```

Если Docker установлен, запустите приложение Docker Desktop и оставьте его открытым.

## Скачайте закрытый репозиторий

Сначала войдите в GitHub через `gh`. Команда задаст несколько вопросов: выберите `GitHub.com`, способ `HTTPS` и вход через браузер. Войдите в тот аккаунт, которому владелец проекта выдал доступ.

```sh
gh auth login
gh auth setup-git
```

Затем скачайте проект и перейдите в его папку:

```sh
git clone https://github.com/only1stumpy/Minecraft-Material-Tracker.git
cd Minecraft-Material-Tracker
```

Если GitHub пишет, что репозиторий не найден или доступ запрещён, попросите владельца проекта проверить приглашение. Для приватного репозитория такая ошибка обычно означает, что у вашего аккаунта ещё нет доступа.

## Запустите локальную базу данных

База данных — отдельная программа, в которой сайт хранит пользователей, постройки и материалы. В Docker Desktop откройте терминал и выполните одну команду:

```sh
docker run --name antville-local-postgres --detach --publish 127.0.0.1:5432:5432 --env POSTGRES_USER=antville --env POSTGRES_PASSWORD=antville_local_only --env POSTGRES_DB=antville --volume antville-local-postgres-data:/var/lib/postgresql/data postgres:16
```

Команда скачает PostgreSQL 16 и запустит его только на этом компьютере. Данные сохраняются в Docker volume `antville-local-postgres-data`, поэтому остановка компьютера не стирает базу.

Если вы уже запускали эту команду раньше и Docker сообщает, что контейнер с таким именем существует, запустите старый контейнер:

```sh
docker start antville-local-postgres
```

Если сообщение говорит, что порт `5432` уже занят, в команде Docker замените `127.0.0.1:5432:5432` на `127.0.0.1:5433:5432`. Ниже в адресе базы тогда тоже замените порт `5432` на `5433`.

## Настройте адрес базы и файловое хранилище

В папке проекта сделайте копию примера настроек. В Windows PowerShell выполните:

```powershell
Copy-Item .env.example .env
```

В macOS или Linux выполните:

```sh
cp .env.example .env
```

Откройте файл `.env` в текстовом редакторе. Найдите строку `DATABASE_URL` и замените её на адрес локальной базы:

```env
DATABASE_URL="postgresql://antville:antville_local_only@localhost:5432/antville?schema=public"
```

Если вы выбрали порт `5433`, поставьте `localhost:5433` вместо `localhost:5432`.

В строке `BLOB_READ_WRITE_TOKEN` вставьте тестовый токен, который вы получили от владельца проекта. Токен нужен для загрузки скриншотов и схем. Если сейчас файлы загружать не нужно, оставьте значение пустым.

Не отправляйте `.env` другим людям и не добавляйте его в Git. В нём могут быть секреты. В репозитории уже настроено игнорирование этого файла.

## Установите зависимости и подготовьте сайт

В терминале, находясь внутри папки `Minecraft-Material-Tracker`, выполните команды по очереди:

```sh
npm ci
npx prisma validate
npm run db:deploy
```

Что они делают:

- `npm ci` скачивает точные версии библиотек, записанные в проекте.
- `npx prisma validate` проверяет описание базы данных. Оно не меняет данные.
- `npm run db:deploy` создаёт таблицы в вашей локальной базе.

Если последняя команда пишет, что не может подключиться к базе, вернитесь к шагу с Docker и проверьте, что контейнер запущен и `DATABASE_URL` содержит тот же пароль и порт.

## Создайте первый локальный аккаунт

Регистрации на сайте нет: проект закрытый. Для пустой локальной базы создайте первого администратора. Вместо `MinecraftNick` укажите свой игровой ник из 3–16 латинских букв, цифр или знаков `_`:

```sh
npm run admin:bootstrap -- MinecraftNick
```

В терминале появится временный пароль. Сохраните его сразу: команда покажет пароль только один раз. Не отправляйте его в общий чат и не сохраняйте в Git.

Если база уже содержит администратора, эта команда откажется работать. В этом случае не запускайте её повторно: войдите под существующим администратором или попросите его создать для вас аккаунт через раздел `/admin`.

## Запустите сайт и войдите

Запустите сайт:

```sh
npm run dev
```

Не закрывайте это окно терминала: пока в нём работает команда, работает и сайт. Откройте в браузере [http://localhost:3000](http://localhost:3000) и войдите с игровым ником и временным паролем. При первом входе сайт попросит заменить временный пароль.

Чтобы остановить сайт, вернитесь в терминал и нажмите `Ctrl+C`. Чтобы запустить его снова, выполните `npm run dev` ещё раз. Если компьютер перезапускался, сначала откройте Docker Desktop и запустите базу командой `docker start antville-local-postgres`.

После входа администратор может создать отдельные локальные аккаунты через `/admin`. Пользователи и постройки из локальной копии не появляются на рабочем сайте.

## Проверки перед отправкой изменений

Перед тем как отдавать изменения кода на проверку, выполните:

```sh
npm run lint
npm run typecheck
npm test
npm run build
```

Если меняли только документацию, проверьте, что `git diff --check` не находит ошибок, а ссылки ведут на существующие файлы.

В проверке кода CI также запускается на PostgreSQL 16 и версиях Node.js `22.18.0` и `24.11.0`.

## Если что-то пошло не так

| Что вы видите | Что проверить |
| --- | --- |
| GitHub пишет `Repository not found` или `Permission denied` | Войдите в правильный GitHub-аккаунт (`gh auth status`) и попросите владельца выдать доступ к приватному репозиторию. |
| Docker пишет, что не может подключиться к серверу | Откройте Docker Desktop и дождитесь, пока он запустится. |
| Prisma пишет `Can't reach database server` или `P1001` | Проверьте, запущен ли `antville-local-postgres`, и совпадают ли порт в Docker и `DATABASE_URL`. |
| Prisma пишет `Authentication failed` или `P1000` | Пароль в `DATABASE_URL` должен совпадать с `POSTGRES_PASSWORD` в команде Docker. |
| Сайт просит сменить пароль | Это ожидаемо при первом входе с временным паролем. Установите свой постоянный пароль. |
| Загрузка скриншота или схемы не работает | Проверьте, что `BLOB_READ_WRITE_TOKEN` заполнен тестовым токеном в `.env`, затем остановите и заново запустите `npm run dev`. |
| Порт `3000` уже занят | Запустите сайт на другом порту: `npm run dev -- --port 3001`, затем откройте `http://localhost:3001`. |

Если просите помощи, можно прислать текст ошибки. Не прикладывайте `.env`, пароли, токены или адрес рабочей базы.
