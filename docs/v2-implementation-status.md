# Статус Minecraft Material Tracker 2.0

Эта страница сверяет техническое задание с кодом, непрерывной интеграцией (CI) и рабочим сайтом. В ней отдельно отмечено, что уже выпущено и какие проверки ещё нужно пройти.

## Текущее состояние выпуска

- PR [#21](https://github.com/only1stumpy/Minecraft-Material-Tracker/pull/21) влит в `master` коммитом `4dbaa2a`.
- CI проверил код на Node.js 22.18 и 24.11 с PostgreSQL 16: миграции, тесты, проверка стиля, TypeScript, сборка и тестовое восстановление PostgreSQL из резервной копии.
- Развёртывание в рабочей среде Vercel завершилось со статусом `Ready`. Быстрая проверка работоспособности: `/` перенаправляет на вход (`307`), `/login` отвечает `200`, `/api/health` отвечает `200`. Проверка работоспособности также подтверждает соединение с базой через `SELECT 1`; это не заменяет полный пользовательский сценарий. Регион функции подтверждён как `arn1`.
- Регион PostgreSQL по данным подключения пока неизвестен. База определяется как Prisma Postgres.
- Предварительные развёртывания Vercel пропускаются настройкой `ignoreCommand`. Предварительное развёртывание нельзя включать для записи в рабочую базу данных; для него нужны отдельная база и отдельные секреты.
- Снимок рабочего Blob создался с `0 объектов`. Это не является проверкой резервной копии данных реального файла и её восстановления.
- Полная выгрузка рабочей базы данных и восстановление этой копии не выполнены: прямое подключение к рабочей базе данных с текущего компьютера не отвечает. Миграции применены сборкой Vercel, но восстановление тестовой копии в CI не подтверждает восстановление реальных данных.

## Что подтверждает CI

CI запускает приложение на Node.js 22.18 и 24.11 с PostgreSQL 16. Проверяются стиль кода, TypeScript, сборка, миграции Prisma, парсер схем, арифметика, права, ограничение частоты запросов, уведомления, конкурентные операции материалов и склада, а также тестовое восстановление PostgreSQL из специальной выгрузки в изолированную базу. Это подтверждает код и тестовые данные; CI не доказывает состояние рабочей среды, задержку из сетей игроков или восстановление копии настоящих данных.

Перед отправкой изменений можно запустить локально:

```sh
npm run lint
npm run typecheck
npm test
npx prisma validate
npm run build
git diff --check
```

## Что осталось после выпуска

1. Не включать предварительные развёртывания Vercel до появления отдельной базы и секретов: предварительное развёртывание не должно писать в рабочую базу данных.
2. Снять защищённую резервную копию рабочей базы, проверить восстановление в изолированной среде и отдельно проверить восстановление настоящего Blob-файла.
3. Замерить задержку из сетей игроков России и Приднестровья и выяснить регион PostgreSQL.
4. Выполнить многопользовательскую проверку, загрузить реальные игровые файлы и вручную проверить клавиатуру, контраст и мобильный экран.

При создании модератора используйте [инструкцию для администратора](production-moderator.md). Она описывает действия через интерфейс сайта и безопасный запасной вариант через командную строку (CLI) без сохранения секретов рабочей среды в локальный файл `.env`.
