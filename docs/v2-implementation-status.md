# Статус реализации Antville Builder 2.0

Карта сверяет требования из [`docs/antville-builder-2.0.md`](antville-builder-2.0.md) с текущим кодом и эксплуатационными документами. Статус `Реализовано в коде` означает, что соответствующие маршруты, компоненты, скрипты или модели найдены в репозитории; production-проверка указывается отдельно. `Частично` означает, что часть требования есть в исходниках, а часть явно указана в ограничениях. `Внешняя проверка` означает, что доказательство зависит от production, PostgreSQL, Vercel или реальных сетей игроков.

В этой карте разделены два вида доказательств: ссылки в таблице подтверждают наличие реализации в исходниках, а production-проверка засчитывается только после отдельного запуска с зафиксированным результатом. Обновлено 14 октября 2026 года после выпуска V2 в Vercel Production.

## Проверки и production-развёртывание

Проверено 14 октября 2026 года:

- `npm run lint -- --quiet` — успешно;
- `npm run typecheck` — успешно;
- `npm test` — успешно, 7 test files; локальная DB-проверка конкуренции пропущена без `TEST_DATABASE_URL`, а PostgreSQL-сценарий отдельно прошёл в GitHub CI;
- `npx prisma validate` — успешно;
- локальная Next.js production build — успешно;
- обе новые Prisma-миграции применены Vercel Production build; повторная production-сборка сообщила `No pending migrations to apply`;
- Production health endpoint возвращал HTTP 200; production-вход и страницы `/admin`, `/moderation` проверены. Имя тестового аккаунта, пароль и внутренние идентификаторы deployment не записываются в публичный репозиторий;
- 14 октября 2026 года GET `https://antville.vercel.app/api/health` вернул HTTP 200 и `{"status":"ok"}`; сокращённая цепочка `x-vercel-id` `fra1::arn1::…` подтвердила выполнение функции в `arn1`. Один запрос с текущего хоста занял 1.29 секунды; egress проходит через proxy, поэтому это единичная техническая проверка, а не измерение сетей игроков. Реальные сети игроков, восстановление production backup и восстановление загруженных Blob-объектов остаются непроверенными;
- private Blob Store и `/api/uploads`: временный `.txt` загружен клиентским SDK, прочитан с серверной авторизацией и удалён; без сессии upload route вернул HTTP 401, с чужим Origin — HTTP 403, скачивание Blob без авторизации — HTTP 403. Загрузка/скачивание схем и скриншотов в карточке, восстановление версии и граничные проверки размеров/форматов остаются непроверенными;
- Markdown validator, `git diff --check` и JSON-проверка `vercel.json` проходят.

Preview-сборки сейчас пропускаются, поскольку Preview и Production настроены на одну базу PostgreSQL. Включайте Preview только после подключения отдельной тестовой базы. GitHub CI на Node 22 и 24 с PostgreSQL 16 прошёл, включая шаг `db:backup` → restore в отдельную базу и проверку синтетического fixture. Production-восстановление backup, восстановление загруженных Blob-объектов и полное ручное тестирование production остаются внешними проверками. Для выдачи роли `MODERATOR` используйте [панель администратора и production runbook](production-moderator.md).
