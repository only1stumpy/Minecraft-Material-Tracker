# Статус Minecraft Material Tracker 2.0

Эта страница сверяет техническое задание с кодом, CI и рабочим сайтом. В ней отдельно отмечено, что уже выпущено и какие проверки ещё нужно пройти.

## Текущее состояние выпуска

- PR [#21](https://github.com/only1stumpy/Minecraft-Material-Tracker/pull/21) влит в `master` коммитом `4dbaa2a`.
- CI проверил код на Node.js 22.18 и 24.11 с PostgreSQL 16: миграции, тесты, lint, TypeScript, build и тестовое восстановление PostgreSQL из backup.
- Production-деплой Vercel завершился со статусом `Ready`. Smoke-check: `/` перенаправляет на вход (`307`), `/login` отвечает `200`, `/api/health` отвечает `200`. Health-check также подтверждает соединение с базой через `SELECT 1`; это не заменяет полный пользовательский сценарий. Регион функции подтверждён как `arn1`.
- Регион PostgreSQL по данным подключения пока неизвестен. База определяется как Prisma Postgres.
- Vercel Preview пропускается настройкой `ignoreCommand`. Preview нельзя включать для записи в production DB; для него нужна отдельная база и отдельные секреты.
- Snapshot production Blob создался с `0 объектов`. Это не является проверкой backup байтов реального файла и его восстановления.
- Полный dump production-БД и восстановление этой копии не выполнены: прямое подключение к production-БД с текущего компьютера не отвечает. Миграции применены Vercel-сборкой, но CI-восстановление тестовой копии не подтверждает восстановление реальных данных.

## Что подтверждает CI

CI запускает приложение на Node.js 22.18 и 24.11 с PostgreSQL 16. Проверяются lint, TypeScript, build, Prisma-migration, парсер схем, арифметика, права, rate limit, уведомления, конкурентные операции материалов и склада, а также тестовое восстановление PostgreSQL из custom dump в изолированную базу. Это подтверждает код и тестовые данные; CI не доказывает состояние production, задержку из сетей игроков или восстановление копии настоящих данных.

Перед отправкой изменений можно запустить локально:

```sh
npm run lint
npm run typecheck
npm test
npx prisma validate
npm run build
git diff --check
```

## Что осталось после выпуска

1. Не включать Vercel Preview до появления отдельной базы и секретов: Preview не должен писать в production DB.
2. Снять защищённый production backup базы, проверить восстановление в изолированной среде и отдельно проверить восстановление настоящего Blob-файла.
3. Замерить задержку из сетей игроков России и Приднестровья и выяснить регион PostgreSQL.
4. Выполнить multiuser-проверку, загрузить реальные игровые файлы и вручную проверить клавиатуру, контраст и мобильный экран.

При создании модератора используйте [инструкцию для администратора](production-moderator.md). Она описывает действия через интерфейс сайта и безопасный CLI fallback без сохранения production-секретов в env-файл.
