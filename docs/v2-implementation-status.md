# Статус Minecraft Material Tracker 2.0

Эта страница сверяет код репозитория с [техническим заданием](antville-builder-2.0.md). Статусы разделены на четыре независимые проверки: что написано в коде, что прошло CI, что проверено на production и что ещё требуется для выпуска.

## Текущее состояние выпуска

- PR [#21](https://github.com/only1stumpy/Minecraft-Material-Tracker/pull/21) открыт. Этот документ не означает, что PR уже влит.
- Код PR и CI проверены успешно: Node.js 22.18 и 24.11, PostgreSQL 16, миграции, тесты, lint, TypeScript, build и тестовое восстановление PostgreSQL из backup.
- Production `/api/health` ответил `200`; это подтверждает доступность приложения и проверку `SELECT 1`, но не полный пользовательский сценарий. Регион функции подтверждён как `arn1`.
- Регион PostgreSQL по данным подключения пока неизвестен. База определяется как Prisma Postgres.
- Vercel Preview пропускается настройкой `ignoreCommand`. Preview нельзя включать для записи в production DB; для него нужна отдельная база и отдельные секреты.
- Snapshot production Blob создался с `0 объектов`. Это не является проверкой backup байтов реального файла и его восстановления.
- Production dump/restore ещё не подтверждены. Новая миграция `20261014030000_controlled_surplus` также ещё не подтверждена на production.

## Что подтверждает CI

CI запускает приложение на Node.js 22.18 и 24.11 с PostgreSQL 16. Проверяются lint, TypeScript, build, Prisma-migration, парсер схем, арифметика, права, rate limit, уведомления, конкурентные операции материалов и склада, а также тестовое восстановление PostgreSQL из custom dump в изолированную базу. Это подтверждает код и тестовые данные; CI не доказывает состояние production, задержку из сетей игроков или восстановление копии настоящих данных.

Перед отправкой изменений можно запустить локально:

```sh
npm run lint
npm run typecheck
npm test
npx prisma validate
npm run build
git diff --check
```

## Незакрытые действия перед выпуском

1. Не включать Vercel Preview до появления отдельной базы и секретов: Preview не должен писать в production DB.
2. Снять защищённый production backup базы, проверить restore в изолированной среде и отдельно проверить восстановление настоящего Blob-файла.
3. Подтвердить применение новой миграции `20261014030000_controlled_surplus` на production после проверки backup.
4. Замерить задержку из сетей игроков России и Приднестровья и выяснить регион PostgreSQL.
5. Выполнить multiuser smoke-check, загрузку реальных файлов и ручную проверку клавиатуры, контраста и телефона.
6. После этого влить PR #21 и отдельно подтвердить production deployment.

При создании модератора используйте [инструкцию для администратора](production-moderator.md). Она описывает действия через интерфейс сайта и безопасный CLI fallback без сохранения production-секретов в env-файл.
