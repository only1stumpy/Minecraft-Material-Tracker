# Выдача роли модератора в Minecraft Material Tracker (MMT)

Эта инструкция предназначена для администратора закрытого сервиса. Она описывает, как выдать роль `MODERATOR` участнику Minecraft Material Tracker. Если сайт работает, используйте панель `/admin`. Запасной вариант через Vercel CLI нужен только на случай, когда панель временно недоступна.

Команда CLI меняет роль уже существующего аккаунта `PLAYER`. Она не создаёт аккаунт, не меняет пароль и не запускает миграции базы данных.

## Обычный способ: панель `/admin`

Если сайт работает, меняйте роль через него. Подключаться к базе данных и копировать её ключи не нужно.

1. Войдите на [рабочий сайт](https://antville.vercel.app) под аккаунтом `ADMIN` и откройте [панель управления](https://antville.vercel.app/admin).
2. Для нового модератора создайте участника и выберите роль «Модератор». Сайт один раз покажет временный пароль; передайте его человеку закрытым способом.
3. Для существующего участника найдите его ник и выберите `MODERATOR` в столбце ролей.
4. Попросите участника войти ещё раз. После смены роли старые сеансы будут отозваны.

Изменения сохраняются в рабочей базе через сервер Vercel и попадают в журнал действий панели.

## Что изменит запасная CLI-команда

Скрипт `admin:grant-moderator` выполняет все изменения одной транзакцией:

- меняет роль найденного участника с `PLAYER` на `MODERATOR`;
- увеличивает `sessionVersion` и удаляет его активные сеансы;
- добавляет в `AuditLog` запись `USER_ROLE_CHANGED`.

После этого участник должен войти снова. Если аккаунт заблокирован, смена роли не снимет блокировку: сначала разблокируйте его через `/admin`. Аккаунт с ролью `ADMIN` скрипт не изменяет.

## Что понадобится

- Рабочий аккаунт `ADMIN` для панели или уже существующий аккаунт `PLAYER` с точным Minecraft-ником для CLI-команды.
- Git и версия Node.js, указанная в [`package.json`](../package.json): `22.12+` в ветке `22.x` или `24.11+` в ветке `24.x`.
- Вход в нужный Vercel-аккаунт, доступ к проекту и сетевое подключение с вашего компьютера к рабочей базе PostgreSQL.
- Клон репозитория с установленными зависимостями `@prisma/client`.
- Уже применённые миграции рабочей базы, в том числе миграция, которая добавляет роль `MODERATOR`: [`20261014010000_builder_v2/migration.sql`](../prisma/migrations/20261014010000_builder_v2/migration.sql).

Для подключения скрипту нужна переменная `DATABASE_URL` из рабочего окружения Vercel. Не скачивайте рабочий `.env`, не печатайте значение переменной в терминал и не отправляйте его в чат. Если нужная миграция ещё не применена, остановитесь и выполните обычный выпуск по [инструкции по развёртыванию и восстановлению](stage-1-operations.md). Не добавляйте `npm run db:deploy` к команде выдачи роли: этот скрипт миграции не запускает.

## Подключите клон к нужному проекту Vercel

Все команды этого раздела выполняйте из корневой папки клона. В репозитории сейчас указаны проект `antville` и область команды `only1stumpys-projects`. Перед запуском проверьте их: если проект или команда переименованы, используйте новые значения из вывода Vercel.

1. Проверьте, под каким аккаунтом выполнен вход:

   ```sh
   npx vercel whoami
   ```

   Если CLI сообщает, что вход не выполнен, запустите `npx vercel login` и завершите вход в браузере.

2. Посмотрите доступные команды и проекты:

   ```sh
   npx vercel teams list
   npx vercel project ls --scope only1stumpys-projects
   npx vercel project inspect antville --scope only1stumpys-projects
   ```

   Убедитесь, что нашли именно нужный проект. Если имя проекта или область команды отличаются, подставьте правильные значения во все команды ниже.

3. Привяжите текущую папку к проверенному проекту:

   ```sh
   npx vercel link --yes --project antville --scope only1stumpys-projects
   ```

   Привязка сохраняет сведения о проекте локально. Она не скачивает и не записывает в репозиторий рабочие секреты. Убедиться, что в Vercel есть нужная переменная, можно по её имени:

   ```sh
   npx vercel env ls production --scope only1stumpys-projects
   ```

   В списке должна быть `DATABASE_URL`. Не запускайте `vercel env pull`: для этой операции скачивать секрет на компьютер не нужно. Команда выдачи роли ниже всё равно указывает проект и область команды явно.

Подробности о `env run` и `link` есть в [официальной документации Vercel CLI](https://vercel.com/docs/cli/env) и [документации `vercel link`](https://vercel.com/docs/cli/link).

## Выдайте роль через CLI

Если зависимости ещё не установлены, один раз выполните в корне клона:

```sh
npm ci
```

Затем сверьте точный Minecraft-ник и запустите команду ниже, заменив `MinecraftNick` на ник уже существующего участника. Выполняйте команду из корня клона:

```sh
env -u DATABASE_URL npx vercel --cwd /tmp --scope only1stumpys-projects env run --project antville -e production -- node "$PWD/scripts/grant-moderator.mjs" MinecraftNick
```

Эти параметры защищают от подключения не к той базе. `vercel env run` передаёт процессу переменные выбранной среды Vercel, но CLI может также подхватить локальные `.env` и `.env.local`. Если в одном из этих файлов задана своя `DATABASE_URL`, она может направить команду в локальную базу. Поэтому `env -u DATABASE_URL` удаляет переменную из текущего окружения оболочки, а `--cwd /tmp` не даёт CLI читать файлы `.env` из клона. Путь `"$PWD/scripts/grant-moderator.mjs"` при этом указывает на скрипт в корне клона, а `--project` и `--scope` явно задают Vercel-проект и область команды.

Скрипт запускается на вашем компьютере и подключается к PostgreSQL через переданную Vercel переменную. На компьютере должен быть сетевой доступ к рабочей базе. Команда не открывает порт базы, не выполняет произвольный SQL и не выводит значение `DATABASE_URL`.

При успехе скрипт выведет:

```text
Готово: MinecraftNick теперь MODERATOR. Сессии отозваны, запись добавлена в AuditLog.
```

Если роль уже выдана, повторный запуск ничего не меняет и выводит:

```text
Аккаунт MinecraftNick уже MODERATOR; изменений не требуется.
```

## Частые ошибки

Сначала проверьте код завершения команды. Не запускайте её повторно вслепую.

| Сообщение | Что случилось | Что делать |
| --- | --- | --- |
| `Аккаунт MinecraftNick не найден. Сначала создайте PLAYER через панель /admin.` | Участника с таким ником нет в рабочей базе. | Создайте аккаунт `PLAYER` через `/admin`, затем повторите команду с тем же ником. |
| `Аккаунт ... уже ADMIN; понижение роли запрещено.` | Указанный аккаунт уже администратор. | Не меняйте роль этим скриптом. Проверьте ник. |
| `Использование: npm run admin:grant-moderator -- MinecraftNick` | Ник не указан или не подходит: допустимы 3–16 символов `A–Z`, `a–z`, `0–9` и `_`. | Исправьте аргумент и запустите команду снова. |
| `Не удалось изменить роль. Проверьте DATABASE_URL, миграции и доступ к PostgreSQL.` | Не удалось подключиться к базе или выполнить транзакцию. | Проверьте проект Vercel, сетевой доступ и наличие миграций. Повторите только безопасную команду выше с `env -u DATABASE_URL`, `--cwd /tmp` и путём через `$PWD`. Не печатайте секрет и не выполняйте ручной SQL. |
| Проект не найден, недоступна область команды или CLI просит войти | Выполнен вход не в тот аккаунт или выбраны неправильные проект/область команды. | Повторите `whoami`, `teams list`, `project ls` и `project inspect`; сверьте их вывод, затем привяжите правильный проект через `link`. |

Если команда завершилась ошибкой подключения, это не означает, что роль изменилась. Проверьте роль через `/admin`; повторяйте команду только после исправления причины.

## Проверьте результат

1. Войдите на рабочий сайт под `ADMIN`, откройте `/admin` и убедитесь, что у участника указана роль `MODERATOR`.
2. Проверьте в последних действиях панели запись `USER_ROLE_CHANGED`.
3. Попросите участника войти заново и открыть `/moderation`.
4. Убедитесь, что модератору доступны его рабочие разделы. `/admin` остаётся доступна только аккаунтам `ADMIN`.

## Если нужно отменить выдачу роли

У CLI-скрипта нет обратной команды. Если роль выдана ошибочно, войдите под `ADMIN`, откройте `/admin`, выберите для участника роль `PLAYER` и сохраните изменения. Панель отзовёт его активные сеансы и запишет смену роли в `AuditLog`.

После этого участник должен войти снова. Если `/admin` временно недоступна, не меняйте рабочую базу вручную и не пытайтесь передать обратную роль скрипту `admin:grant-moderator`. Дождитесь восстановления панели или используйте отдельную документированную процедуру администратора.
