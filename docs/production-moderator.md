# Выдача роли модератора в production

Эта инструкция нужна администратору закрытого сервиса. Она переводит уже существующий аккаунт `PLAYER` в роль `MODERATOR` через Vercel CLI и production-базу. Команда не создаёт пользователя, не меняет пароль и не применяет миграции.

## Обычный способ: панель администратора

Если сайт работает, не подключайтесь к базе напрямую:

1. Войдите в production-сайт под `ADMIN` и откройте [`/admin`](https://antville.vercel.app/admin).
2. Для нового модератора создайте пользователя и выберите роль `Модератор`. Сайт один раз покажет временный пароль; передайте его игроку закрытым способом.
3. Для уже существующего игрока найдите строку с его ником и поменяйте роль в списке ролей на `MODERATOR`.
4. Попросите игрока войти заново. При смене роли сайт отзывает его старые сессии.

Эти действия сохраняются в production-базу через сервер Vercel и записываются в журнал аудита. Ключи БД на компьютер скачивать не нужно. Следующие разделы описывают резервный CLI-путь, когда панель временно недоступна.

## Что изменится

Скрипт `admin:grant-moderator` в одной транзакции:

- меняет роль найденного пользователя на `MODERATOR`;
- увеличивает `sessionVersion` и удаляет его активные сессии;
- добавляет запись `USER_ROLE_CHANGED` в `AuditLog`.

После этого пользователь должен войти заново. Если аккаунт заблокирован, роль изменится, но вход останется запрещённым: сначала разблокируйте его в `/admin`. Существующий `ADMIN` скрипт не понижает.

## Перед началом

Нужны:

- доступ `ADMIN` к рабочему сайту или другой согласованный способ создать пользователя;
- аккаунт с точным Minecraft-ником, который уже существует в production и сейчас имеет роль `PLAYER`;
- Git, Node.js одной из поддерживаемых версий из [`package.json`](../package.json): `22.12+` в ветке `22.x` или `24.11+` в ветке `24.x`;
- доступ к Vercel-проекту и возможность подключиться к production PostgreSQL с вашего компьютера;
- установленная зависимость `@prisma/client` из репозитория;
- применённые production-миграции, включая миграцию, которая добавляет `MODERATOR`: [`20261014010000_builder_v2/migration.sql`](../prisma/migrations/20261014010000_builder_v2/migration.sql).

Для выдачи роли скрипт использует production-переменную `DATABASE_URL`. Не скачивайте production `.env`, не выводите значение переменной в терминал и не присылайте его в чат. Если миграция ещё не применена, остановитесь и проведите обычный выпуск по [runbook развёртывания и восстановления](stage-1-operations.md). Не добавляйте `npm run db:deploy` к команде выдачи роли: grant-операция сама миграции не запускает.

## Подключите каталог к правильному Vercel-проекту

Выполняйте команды из корня клона репозитория. В этом проекте текущие значения — проект `antville` и scope `only1stumpys-projects`; всё равно сверяйте их выводом команд, особенно если проект переименовали.

1. Проверьте, под каким Vercel-аккаунтом выполнен вход:

   ```sh
   npx vercel whoami
   ```

   Если CLI отвечает, что вход не выполнен, запустите `npx vercel login` и завершите вход в браузере.

2. Посмотрите доступные команды и проекты:

   ```sh
   npx vercel teams list
   npx vercel project ls --scope only1stumpys-projects
   npx vercel project inspect antville --scope only1stumpys-projects
   ```

   В списке найдите нужный проект. Если у вашей команды другой scope или имя проекта, подставьте значения из вывода вместо `only1stumpys-projects` и `antville`.

3. Свяжите текущую папку с найденным проектом:

   ```sh
   npx vercel link --yes --project antville --scope only1stumpys-projects
   ```

   Эта команда сохраняет локальную привязку проекта. Она не печатает и не коммитит production-секреты. Для проверки имён переменных можно посмотреть только список:

   ```sh
   npx vercel env ls production --scope only1stumpys-projects
   ```

   В списке должна быть `DATABASE_URL`. Не используйте `vercel env pull` для этой операции: скачивать production-секреты на диск не требуется. Для самой grant-операции ниже привязка не используется: команда явно указывает проект и scope и запускает CLI с чистым рабочим каталогом.

Подробный синтаксис `link` и `env run` приведён в [официальной документации Vercel CLI](https://vercel.com/docs/cli/env) и [документации `vercel link`](https://vercel.com/docs/cli/link).

## Выполните выдачу роли

Если зависимости ещё не установлены, один раз выполните в корне репозитория:

```sh
npm ci
```

У `vercel env run` есть особенность: CLI сначала берёт переменные выбранного окружения Vercel, а затем может добавить локальные `.env.local`/`.env` и экспортированные переменные процесса. Поэтому локальный `DATABASE_URL` способен перекрыть production-значение. Запускайте команду ниже буквально из корня репозитория, заменив `MinecraftNick` на точный ник существующего пользователя:

```sh
env -u DATABASE_URL npx vercel --cwd /tmp --scope only1stumpys-projects env run --project antville -e production -- node "$PWD/scripts/grant-moderator.mjs" MinecraftNick
```

`$PWD` должен указывать на корень клона, где лежит `scripts/grant-moderator.mjs`. Флаг `--cwd /tmp` не переносит скрипт в `/tmp`: он не даёт Vercel CLI читать `.env.local` и `.env` из репозитория. `env -u DATABASE_URL` убирает одноимённую переменную из текущей shell-сессии. Сам скрипт выполняется локально на вашей машине и подключается к PostgreSQL, поэтому запускайте его с компьютера, откуда есть сетевой доступ к production DB. Команда не открывает порт базы, не выполняет произвольный SQL и не показывает `DATABASE_URL`.

Ожидаемый успешный вывод:

```text
Готово: MinecraftNick теперь MODERATOR. Сессии отозваны, запись добавлена в AuditLog.
```

Повторный запуск для уже выданной роли безопасен:

```text
Аккаунт MinecraftNick уже MODERATOR; изменений не требуется.
```

## Если команда завершилась ошибкой

Сначала проверьте код завершения команды и не повторяйте её вслепую. Наиболее частые ответы:

| Вывод | Что это означает | Что делать |
| --- | --- | --- |
| `Аккаунт MinecraftNick не найден. Сначала создайте PLAYER через панель /admin.` | В базе нет пользователя с таким ником. | Создайте `PLAYER` через `/admin`, затем повторите команду с тем же ником. |
| `Аккаунт ... уже ADMIN; понижение роли запрещено.` | Вы выбрали администратора. | Не понижайте роль этим скриптом. Проверьте нужный ник. |
| `Использование: npm run admin:grant-moderator -- MinecraftNick` | Ник отсутствует или не соответствует 3–16 символам `[A-Za-z0-9_]`. | Исправьте аргумент и запустите снова. |
| `Не удалось изменить роль. Проверьте DATABASE_URL, миграции и доступ к PostgreSQL.` | Скрипт не смог подключиться или выполнить транзакцию. | Проверьте production-проект, сетевой доступ и миграции. Повторите именно безопасную команду с `env -u DATABASE_URL`, `--cwd /tmp` и абсолютным путём через `$PWD`; не печатайте секрет и не выполняйте ручной SQL. |
| Проект не найден, scope недоступен или CLI просит вход | Vercel привязан к другому проекту или аккаунту. | Повторите `whoami`, `teams list`, `project ls` и `link` с правильными значениями. |

Если команда упала на подключении, это не подтверждает изменение роли. Проверьте пользователя через `/admin` и повторяйте только после исправления причины.

## Проверьте результат

1. Войдите в production под `ADMIN`, откройте `/admin` и убедитесь, что у пользователя указана роль `MODERATOR`.
2. В блоке последних действий проверьте запись смены роли. Она должна иметь действие `USER_ROLE_CHANGED`.
3. Попросите пользователя открыть `/moderation` и войти заново. Страница `/admin` остаётся доступной только `ADMIN`.
4. Убедитесь, что модератор может найти карточки и комментарии, скрыть или восстановить их, а также открыть `/warehouse`. Если у него был старый сеанс, он должен быть отклонён после смены роли.

## Безопасный откат

У этого CLI-скрипта нет обратной команды. Если роль выдана ошибочно, войдите под `ADMIN`, откройте `/admin`, выберите у пользователя роль `PLAYER` и сохраните. Серверная операция смены роли снова отзовёт активные сессии и запишет действие в `AuditLog`.

После отката пользователь должен войти заново. Если `/admin` временно недоступен, не меняйте production-базу вручную и не пытайтесь «обратным» аргументом вызвать `admin:grant-moderator`; дождитесь восстановления панели или используйте отдельную документированную операцию администратора.
