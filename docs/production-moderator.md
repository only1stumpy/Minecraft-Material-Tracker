# Выдача роли модератора в production

Роль `MODERATOR` предназначена для модерации построек и комментариев. Модератор не управляет аккаунтами и ролями. `ADMIN` управляет аккаунтами, ролями и настройками, а `PLAYER` создаёт вклад в проекте.

## Обычный путь через панель

1. Откройте развёрнутый Antville Builder и войдите в `/admin` под `ADMIN`.
2. Создайте аккаунт с ролью `PLAYER`, указав Minecraft-ник.
3. Передайте показанный после создания временный пароль игроку по защищённому каналу. Пароль показывается один раз; аккаунт должен сменить его при первом входе.
4. В списке пользователей найдите созданный аккаунт, назначьте ему роль `MODERATOR` и сохраните изменение.
5. Обновите список пользователей и проверьте роль. Пользователь должен войти заново: изменение роли отзывает активные сессии и записывается в `AuditLog`.

Создание аккаунта и смена роли — разные операции. Назначение модератора не сбрасывает пароль и не меняет другие свойства аккаунта.

## Экстренный CLI-путь для Vercel

Используйте его, если панель недоступна, но у вас есть доступ к проекту Vercel. Команда должна выполняться на машине, где уже выполнен `vercel link` для нужного проекта:

```sh
vercel env run -e production -- npm run admin:grant-moderator -- MinecraftNick
```

Команда получает `DATABASE_URL` из production environment через Vercel CLI и передаёт его процессу только на время запуска. Не скачивайте `.env`, не вставляйте URL вручную и не выполняйте SQL или ручное создание хеша пароля. Синтаксис `vercel env run` описан в [официальной документации Vercel](https://vercel.com/docs/cli/env).

### Перед запуском

- Vercel CLI установлен и авторизован; каталог связан с нужным проектом командой `vercel link`.
- В production environment настроен корректный `DATABASE_URL` PostgreSQL.
- На production БД применена миграция с ролью `MODERATOR`.
- Зависимости установлены, используется Node.js 22.12+ или 24.11+ согласно `package.json`.
- Аккаунт уже существует и имеет роль `PLAYER`; CLI не создаёт аккаунты.
- Ник точно соответствует формату Minecraft: 3–16 символов `[A-Za-z0-9_]`.

### Результаты

- `Готово: ... теперь MODERATOR...` — роль изменена, сессии отозваны, аудит записан одной транзакцией.
- `... уже MODERATOR; изменений не требуется.` — повторный запуск безопасен и ничего не меняет.
- `Аккаунт ... не найден...` — сначала создайте `PLAYER` через `/admin`.
- `... уже ADMIN; понижение роли запрещено.` — команда не может понизить администратора.

Скрипт не печатает `DATABASE_URL`, хеши паролей или другие секреты. Любая ошибка подключения или транзакции завершает команду с ненулевым кодом; повторите после проверки переменных и миграций.

## Проверка и откат

После CLI-запуска войдите в `/admin`, обновите список пользователей и проверьте роль и последнюю запись в блоке аудита. Затем попросите пользователя войти снова и сменить временный пароль, если он ещё не был изменён.

Для отката откройте пользователя в панели, назначьте роль `PLAYER` и сохраните. Команда `admin:grant-moderator` намеренно не выполняет понижение ролей; она не сбрасывает пароль при откате. Если в проекте появится отдельная CLI-команда для отката, используйте только её документированный интерфейс.
